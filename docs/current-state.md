# KickMate 현재 구현 상태

이 문서는 계획이 아니라 현재 워킹 트리에서 실제로 동작하고 검증된 범위를 기록한다.
구조적 원칙은 [architecture.md](./architecture.md), 전체 로드맵은
[project-plan.md](./project-plan.md)를 참고한다.

마지막 확인일: 2026-08-19

## 요약

M2.5의 6대6 home 사용자 대 away 봇 경기 흐름이 구현됐다. 사용자는 Canvas에서
기물과 목적지를 고르고 HTML 버튼으로 이동·패스·슛을 선택한다. 패스는 받을 아군,
슛은 골문 행을 직접 고르며 실행 전 실제 공 경로와 수신자·차단자를 확인할 수 있다.
봇은 Web Worker에서 깊이 3으로 탐색하고 3골 선취 또는 경기 전체 60 ply에서 경기를
끝낸다.

```text
저장소·검증 골격          완료
순수 룰 엔진              완료
Lv.1 평가와 탐색          완료
Worker 기반 봇 분석       완료
Canvas 입력과 렌더링      완료
사용자 대 봇 경기 흐름    구현 완료
6대6 핵심 경기 규칙       구현·자동 검증 완료
경기 후 분석·리뷰         미구현
셀프플레이 CLI            미구현
GitHub Pages 배포         완료
```

## 구현 완료 후 남은 확인

2026-08-19에 반복 플레이에서 확인한 재미와 직관성 문제를 해결하기 위해
[핵심 경기 규칙 개편 설계](./superpowers/specs/2026-08-19-core-gameplay-redesign-design.md)를
승인했다. 6대6, 필드 선수 공통 이동, 아군 직접 지정 패스, 골문 직접 조준 슛,
8방향 스틸과 경로 미리보기는 현재 워킹 트리에 구현됐다.

자동 검증은 끝났지만 실제 브라우저 세 경기와 사용자의 재플레이 의향 판단은 아직
기록되지 않았다. 현재 GitHub Pages 배포 URL은 이 워킹 트리를 커밋·푸시하기 전까지
이전 배포판을 제공한다.

## 최근 검증

2026-08-19 워킹 트리에서 다음 명령을 실행했다.

```powershell
npm run check
```

결과:

```text
TypeScript typecheck       통과
Vitest                     113개 테스트 통과
content 검증               통과
64경기 엔진 완주·행동 검사 통과
32경기 Canvas 대상 왕복    통과
초기 6대6 depth-3 탐색     44ms, 5초 기준 통과
```

로컬 개발 서버 `http://localhost:5174/`가 HTTP 200으로 새 진입점을 제공하는 것을
확인했다. 사용자 터미널의 `npm run build`는 13개 모듈과 `engine.worker` 번들을
326ms에 생성하며 통과했다. 관리형 Codex 환경에서는 브라우저 제어 런타임이 경로
오류로 시작되지 않아 실제 세 경기 클릭 검증은 사용자 환경에서 최종 확인해야 한다.

첫 번째 패스 중심 브라우저 점검에서 사용자가 받을 아군을 직접 선택하고, 초록 `✓`와
빨강 `!` 경로를 구분하며, 먼 DF를 겨냥한 패스가 중간 FW에게 먼저 닿는 예고와 실제
결과가 일치하는 것을 확인했다.

2026-08-18에는 GitHub Actions의 Pages `build`와 `deploy` job이 모두 성공했다.
[`https://winteri5coming.github.io/KickMate/`](https://winteri5coming.github.io/KickMate/)에서
새로고침, 실제 경기 플레이와 Worker 봇 응수를 확인했으며 브라우저 Console 오류와
Network 404가 없음을 확인했다.

## 현재 실행 흐름

```text
index.html의 DOM 이벤트
  → main.ts가 입력 좌표와 버튼 행동을 Controller에 전달
  → GameController가 legalMoves로 입력을 해석하고 applyMove로 상태 변경
  → 봇 차례에는 EngineClient가 Worker에 깊이 3 분석 요청
  → Worker가 search 결과를 반환
  → Controller가 봇 수를 적용하고 ClientViewState 발행
  → render.ts가 Canvas와 HTML을 현재 상태로 다시 그림
```

## 구현된 기능

### 엔진

- 13×9 보드와 양 팀 GK 1·DF 2·MF 2·FW 1의 6대6 배치
- 필드 선수 공통 8방향 한 칸 이동과 GK 박스 제한
- `ballPath.ts`의 정확한 선분 경로와 `previewMove()` 판정
- 아군 직접 지정 패스, 골문 행 직접 지정 슛, 8방향 스틸과 보호 한 수
- held·loose 공 상태
- 득점 후 실점 팀 킥오프
- 3골 선취 즉시 종료
- 전체 경기 60 ply 종료와 승·패·무 판정
- 입력 상태를 변경하지 않는 `applyMove()`
- 결정론적 네가맥스·알파베타 탐색과 모든 루트 후보 점수

### 클라이언트 대국

- `ready`, `humanTurn`, `botThinking`, `finished`, `fatalError` 화면 단계
- 게임 시작과 즉시 새 게임
- home 기물 선택과 빈 공간 클릭 해제
- 이동·패스·슛 행동 버튼과 합법 후보 표시
- away 공 소유자 직접 클릭 스틸
- 복수 스틸러가 있을 때 사용할 아군을 다시 선택
- 패스·슛 성공/차단 경로와 실제 수신자·차단자 표시
- 보호 중인 공 소유자의 `◆` 표시
- held 공, loose 공, 선택 기물, 후보, 직전 수 표시
- 봇 분석 중 입력 잠금
- 분석당 5초 제한, Worker 교체를 포함한 최대 3회 자동 시도
- 세 번째 분석 실패 후 오류 화면과 새 게임
- 점수, 현재 ply, 승·패·무 결과 표시

### Task 7에서 확인한 경계

- 사람의 세 번째 골 직후 봇을 호출하지 않고 종료
- 봇의 세 번째 골 직후 사용자 입력을 열지 않고 종료
- 사람 수와 봇 수 각각에서 60 ply 도달 시 종료
- 60 ply의 home 우세, away 우세, 동점 판정
- 종료·오류 상태의 Canvas 입력 무시
- 새 경기에서 `turn=0`, `score=0:0`, `humanTurn` 복원
- 두 번 실패 후 Worker를 교체하고 세 번째 분석 결과 적용
- 세 번 모두 실패하면 `fatalError`, 이후 새 경기 복구
- 다양한 64경기가 보드 범위·좌표 중복·공 소유·턴·점수 불변식을 지키며 종료
- 32경기의 모든 합법 수가 모호하지 않은 Canvas 클릭 대상으로 왕복

## 이전 플레이 점검에서 해결한 사항

### 슛 후보가 하나만 보이던 문제

기존 `dy=-1,0,1` 레이 방식은 위치에 따라 슛 후보가 하나만 생겼다. 현재는 슛 거리
안에서 상대 골문의 3·4·5행을 모두 직접 선택하고, 정확한 선분 경로가 차단 여부를
판정하도록 교체했다.

### 아군 패스 후보 표시 수정

아군 기물로 연결되는 패스 후보는 작은 점이 기물에 가려졌었다. 현재는 선택 가능한
아군 바깥에 테두리를 그리고 공의 실제 경로, 첫 수신자와 차단 여부를 함께 표시한다.

## 아직 구현되지 않은 기능

- 사람 수의 사전 분석과 수 품질 판정
- 최선·좋은 수·부정확·실수·블런더 표시
- 기보 저장과 경기 후 실수 리뷰
- 평가 막대와 추정 승률
- `tools/selfplay.ts` 실제 경기·통계 출력
- 퍼즐 JSON 실행과 제한 턴 내 해법 검산
- `content/pieces.json` 규칙값의 엔진 주입

## 알려진 제약

- `tools/selfplay.ts`는 아직 안내만 출력하고 종료 코드 1을 반환한다.
- `content/pieces.json`의 규칙 수치는 검증되지만 엔진은 현재 같은 값을 코드 상수로 사용한다.
- `content/pieces.json`의 역할별 이동 설명은 새 공통 이동 규칙과 아직 동기화되지 않았다.
- 슛 경로의 첫 기물은 팀과 역할에 관계없이 공을 소유해 슛을 막는다. 유지 여부는 실험 정책이다.
- 이번 변경분의 실제 브라우저 세 경기 확인이 남아 있다.
- 실제 모바일 브라우저 검증은 아직 수행하지 않았다.

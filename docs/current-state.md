# KickMate 현재 구현 상태

이 문서는 계획이 아니라 현재 워킹 트리에서 실제로 동작하고 검증된 범위를 기록한다.
구조적 원칙은 [architecture.md](./architecture.md), 전체 로드맵은
[project-plan.md](./project-plan.md)를 참고한다.

마지막 확인일: 2026-08-22

## 요약

M2.6A의 6대6 home 사용자 대 away 봇 경기 흐름 위에 M2.6B 확률 판정 코어가 구현됐다.
사용자는 Canvas에서 기물과 목적지를 고르고 HTML 버튼으로 이동·패스·슛을 선택한다.
패스는 받을 아군, 슛은 골문 행을 직접 고르며 실행 전 실제 공 경로, 수신자·차단자와
함께 도착·득점 확률 %를 확인할 수 있다. 슛 경로 위 상대 필드 선수는 65%, GK는 75%,
경로 인접 상대는 20% 확률로 개입하며 모든 개입을 뚫으면 득점이다. 판정은 상태·수
FNV 해시 시드로 결정적으로 재현되고, 봇 탐색은 결과 분포의 기대값으로 수를 평가한다.
사람 턴에는 상대 공 소유자의 슛 위협 레인과 확률이 표시된다. 한 팀은 행동 포인트
3개를 쓰며 같은 기물은 팀 턴마다 최대 두 번 행동한다. 압박받은 공 소유자는 버티기 뒤
한 번 이동할 수 있고, 스틸은 100% 결정론을 유지한다. 봇은 Web Worker에서 깊이 3으로
away 팀의 전체 팀 턴을 처리하며, 3골 선취 또는 경기 전체 60 원자 행동에서 경기를
끝낸다.

```text
저장소·검증 골격          완료
순수 룰 엔진              완료
Lv.1 평가와 탐색          완료

사용자 대 봇 경기 흐름    구현 완료

M2.6B 확률 판정·기대값 탐색·위협 표시  구현·자동 테스트 검증 완료
경기 후 분석·리뷰         미구현
```

## M2.6A 구현과 남은 사용자 확인

M2.6A는 현재 워킹 트리에 구현되어 자동 테스트로 검증됐다. `GameState`의
`activeTeam`, `actionsRemaining`, `actionCountByPiece`, `heldFirmPieceId`,
`stealProtection`이 팀 턴, 선수별 행동 제한, 버티기, 재스틸 보호를 표현한다.
`hold`와 `endTurn`은 다른 원자 행동과 같은 `Move`이며, `endTurn`만 `turn`을
증가시키지 않는다. `hold`는 팀 행동을 쓰되 선수별 2행동 상한에는 세지 않는다. 새
소유권의 `stealProtection`은 공을 잃은 팀의 다음 원자 행동 1회 뒤 끝나고, 2인 포위에서는
즉시 무시된다. 자세한 목표와 경계는 [FT&G 벤치마킹 경기 코어 개편 설계](./superpowers/specs/2026-08-22-ftg-inspired-match-core-design.md)를 따른다.

자동 테스트와 실제 브라우저 화면을 통한 자동 입력 10경기는 확인했지만, 사용자가 직접
진행한 세 경기와 모바일 브라우저, 재플레이 의향은 아직 기록되지 않았다. 현재 GitHub
Pages 배포 URL은 이 워킹 트리를 커밋·푸시하기 전까지 이전 배포판을 제공한다.

## 최근 검증

2026-08-22 현재 워킹 트리에서 다음 명령을 실행했다.

```powershell
npm run check
```

결과 (M2.6B 확률 판정 코어 반영 후):

```text
TypeScript typecheck       통과
Vitest                     7 files, 156 tests 통과
content 검증               통과
엔진 집중 테스트            2 files, 64 tests 통과
클라이언트 집중 테스트      5 files, 92 tests 통과
초기 6대6 depth-3 탐색     병렬 테스트 부하에서 약 4.1초, 5초 기준 통과
압박·슛 depth-3 탐색       병렬 테스트 부하에서 약 3.4초, 5초 기준 통과
Vite 프로덕션 빌드          통과, 415ms
```

`rules.test.ts`는 초기와 압박·슛 대표 국면 모두에서 depth-3 탐색이 5초 안에 끝나는지
검증한다. 기대값 탐색 도입으로 depth-3 시간이 종전 약 0.6초에서 단독 실행 기준
2~3초로 늘었다. 5초 기준은 지키지만 브라우저 반복 체감 측정이 필요하며, 초과가
확인되면 확률 분기 가지치기 또는 깊이 조정을 검토한다.

실제 브라우저 Canvas와 버튼을 사용한 고정 전략 10경기는 3승 7패, home 9득점·away
27득점이었다. 패스형 4경기는 0승·0득점, 강제 슛형 3경기는 0승·0득점, 열린 경로를
찾는 드리블형 3경기는 3승·9득점이었다. 이는 확률 표본이 아니라 결정론적 엔진의 세
경로 반복이며, 보호 완화만으로는 차단 슛 0%·열린 슛 100%의 전략 단절을 해결하지
못했다는 회귀 근거로 사용한다.

## 현재 실행 흐름

```text
index.html의 DOM 이벤트
  → main.ts가 입력 좌표와 버튼 행동을 Controller에 전달
  → GameController가 legalMoves로 입력을 해석하고 applyMove로 상태 변경
  → 봇 차례에는 EngineClient가 Worker에 깊이 3 분석 요청
  → Worker가 search 결과를 반환
  → Controller가 봇 수를 적용하고 ClientViewState 발행
  → render.ts가 Canvas와 HTML을 현재 상태로 다시 그림
```

## 구현된 기능

### 엔진

- 13×9 보드와 양 팀 GK 1·DF 2·MF 2·FW 1의 6대6 배치
- 필드 선수 공통 8방향 한 칸 이동과 GK 박스 제한
- `ballPath.ts`의 정확한 선분 경로와 `previewMove()` 판정
- 아군 직접 지정 패스, 골문 행 직접 지정 슛, 8방향 스틸과 다음 행동 1회 보호
- 팀 턴당 3행동, 같은 기물 팀 턴당 최대 2행동, 한 행동 뒤 조기 종료
- 인접 압박, 선수별 행동 상한을 쓰지 않는 `hold`, 2인 포위가 무시하는 `stealProtection`
- 아군 통과 슛, GK 선방 보호, 필드 차단의 결정론적 루즈볼 리바운드
- M2.6B 확률 관문: 슛 경로 위 필드 65%·GK 75% 개입, 경로 인접 20% 영향권 개입(패스·슛 공통)
- `applyMoveOutcomes()`의 결과 분포 열거와 상태·수 FNV 해시 시드의 결정론적 결과 선택
- 결과 분포 기대값으로 수를 평가하는 expectiminimax 탐색과 확률 비례 EV-04
- held·loose 공 상태
- 득점 후 실점 팀 킥오프
- 3골 선취 즉시 종료
- 전체 경기 60 원자 행동 종료와 승·패·무 판정
- 입력 상태를 변경하지 않는 `applyMove()`
- 같은 팀 연속 행동을 루트 관점으로 처리하는 결정론적 minimax·알파베타 탐색과 모든 루트 후보 점수

### 클라이언트 대국

- `ready`, `humanTurn`, `botThinking`, `finished`, `fatalError` 화면 단계
- 게임 시작과 즉시 새 게임
- home 기물 선택과 빈 공간 클릭 해제
- 이동·패스·슛 행동 버튼과 합법 후보 표시
- away 공 소유자 직접 클릭 스틸
- 복수 스틸러가 있을 때 사용할 아군을 다시 선택
- 패스·슛 성공/차단 경로와 실제 수신자·차단자 표시, 도착·득점 확률 % 표기
- 사람 턴에 away 공 소유자의 슛 위협 레인과 골문별 득점 확률 표시
- 보호 중인 공 소유자의 `◆`, 압박·버티기 상태, 필드 리바운드 예상 칸 표시
- held 공, loose 공, 선택 기물, 후보, 직전 수 표시
- 봇 분석 중 입력 잠금
- 분석당 5초 제한, Worker 교체를 포함한 최대 3회 자동 시도
- 세 번째 분석 실패 후 오류 화면과 새 게임
- 점수, 현재 원자 행동, 현재 팀의 남은 행동과 선택 선수 사용 횟수, 승·패·무 결과 표시

### M2.6A 자동 테스트에서 확인한 경계

- 팀 턴 시작 3행동, 행동 소모, 0에서 팀 교대와 선수별 2행동 제한
- 행동 뒤 조기 종료, 득점 뒤 실점 팀의 3행동 킥오프, 60번째 원자 행동 종료
- 압박 중 이동 금지, `hold → move` 뒤 남은 선수 행동, 다음 원자 행동의 `stealProtection` 만료와 2인 포위 예외
- 아군 통과 슛, GK 선방 보호, 필드 리바운드 및 빈 인접 칸 없는 필드 차단
- 같은 팀 연속 행동과 팀 교대에서의 탐색 관점·결정론적 수 정렬
- 봇의 away 팀 전체 턴 처리, 사람 입력 잠금, 버튼과 Canvas 입력 계약
- 64경기가 보드 범위·좌표 중복·공 소유·턴·점수 불변식을 지키며 종료
- 32경기의 모든 targeted 합법 수가 모호하지 않은 Canvas 클릭 대상으로 왕복

## 이전 플레이 점검에서 해결한 사항

### 슛 후보가 하나만 보이던 문제

기존 `dy=-1,0,1` 레이 방식은 위치에 따라 슛 후보가 하나만 생겼다. 현재는 슛 거리
안에서 상대 골문의 3·4·5행을 모두 직접 선택하고, 정확한 선분 경로가 차단 여부를
판정하도록 교체했다.

### 아군 패스 후보 표시 수정

아군 기물로 연결되는 패스 후보는 작은 점이 기물에 가려졌었다. 현재는 선택 가능한
아군 바깥에 테두리를 그리고 공의 실제 경로, 첫 수신자와 차단 여부를 함께 표시한다.

## 아직 구현되지 않은 기능

- 사람 수의 사전 분석과 수 품질 판정
- 최선·좋은 수·부정확·실수·블런더 표시
- 기보 저장과 경기 후 실수 리뷰
- 평가 막대와 추정 승률
- 퍼즐 JSON 실행과 제한 턴 내 해법 검산
- `content/pieces.json` 규칙값의 엔진 주입

## 알려진 제약

- `tools/selfplay.ts`는 전술 4종의 홈·어웨이 16개 매치업을 depth-3로 완주하는
  밸런스 하네스로 구현됐다. 엔진 import가 확장자 없는 경로라 Node 직접 실행 대신
  esbuild 번들 후 실행한다. 2026-08-23 3라운드 측정으로 전술 승률 44~56%, 선공
  홈 6승/어웨이 5승/무 5를 확인했다.
- `content/pieces.json`은 구조와 일부 범위만 검증되며 엔진에 주입되지 않는다. 역할별 이동과 보호 값은 현재 런타임 규칙과도 다르다.
- Vite 프로덕션 빌드는 승인된 비sandbox 실행에서 167ms에 통과했다.
- 대표 성능 fixture는 초기와 압박·슛 국면 두 건이며, 반복 브라우저 응답 시간은 아직 측정하지 않았다.
- M2.6A의 실제 브라우저 세 경기와 모바일 브라우저 검증은 아직 수행하지 않았다.

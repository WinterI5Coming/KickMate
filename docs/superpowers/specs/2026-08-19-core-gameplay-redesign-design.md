# KickMate 핵심 경기 규칙 개편 설계

작성일: 2026-08-19
상태: 사용자 승인 완료, 구현 전

## 1. 배경과 목표

S2는 사용자 대 봇 한 경기를 완주할 수 있지만 반복 플레이에서 다음 문제가 확인됐다.

- 팀당 4명이라 선택지와 선수 간 상호작용이 적다.
- 고정 기울기 슛은 같은 위치처럼 보여도 가능한 골문이 달라 예측하기 어렵다.
- 8방향 레이 패스는 사용자가 원하는 아군을 직접 선택하지 못한다.
- 상하좌우 한 칸에서만 가능한 스틸은 기회가 드물고 발견하기 어렵다.
- 화면에서 보이는 슛길과 실제 차단 판정이 어긋난다고 느낄 수 있다.

이번 개편은 로그라이크 성장을 구현하지 않고 한 경기 자체의 조작 의도와 판정
예측 가능성을 먼저 개선한다. 목표 플레이 감각은 판정은 명확하지만 패스·슛·스틸
기회가 지금보다 자주 생기는 전술과 난전의 혼합형이다.

## 2. 범위

### 포함

- 6대6 초기 진형과 필드 선수 공통 이동
- 골문 직접 조준 슛과 아군 직접 지정 패스
- 패스와 슛의 공통 선분 경로 판정
- 8방향 인접 스틸과 한 턴 보호 표시
- 성공·차단 경로와 실제 수신자 표시
- 상황별 한 줄 조작 안내
- 변경된 규칙의 엔진·클라이언트·자동 경기 검증

### 제외

- 선수 경험치, 레벨, 능력치
- 타겟터·윙어·포처 같은 세부 역할
- 진형 선택 UI
- 턴당 복수 행동이나 행동 포인트
- 무작위 슛·패스·스틸 판정
- 승리 조건과 최대 ply 변경

로그라이크 역할은 공통 기본 조작 위에 특수 이동 또는 패스·슛·스틸 특징을 추가하는
후속 설계로 분리한다. 이번 구현에서는 미래 확장을 위한 빈 타입이나 임시 능력치를
미리 만들지 않는다.

## 3. 경기 기반

| 항목 | 규칙 |
|---|---|
| 보드 | 13×9 유지 |
| 팀 | home 사용자, away 봇 |
| 인원 | 팀당 6명 |
| 구성 | GK 1, DF 2, MF 2, FW 1 |
| 턴 | 이동·패스·슛·스틸 중 행동 하나 |
| 종료 | 3골 선취 또는 경기 전체 60 ply |
| 판정 | 결정론적, 무작위 없음 |
| 봇 | Web Worker 깊이 3, 분석당 5초 제한 |

턴당 행동 하나는 첫 플레이테스트 기준이다. 새 이동 규칙에서 전개가 느리다고 확인되면
후속 개편에서 복수 행동을 별도로 설계한다.

## 4. 초기 진형과 킥오프

home 기본 좌표는 다음과 같다.

| 포지션 | 좌표 |
|---|---|
| GK | (0,4) |
| DF | (2,2), (2,6) |
| MF | (4,2), (4,6) |
| FW | (5,4) |

away는 유효한 최대 좌표 (12,8)을 기준으로 home 배치를 좌우·상하 미러링한다.
경기 시작과 득점 후에는 킥오프 팀의 첫 번째 MF가 센터 (6,4)에서 공을 소유한다.
나머지 선수는 기본 좌표로 돌아가며 스틸 보호는 초기화한다.

## 5. 이동

DF·MF·FW는 포지션과 관계없이 다음 공통 이동을 사용한다.

~~~text
주변 8방향 한 칸
→ 보드 안의 빈 칸만 가능
~~~

GK도 8방향 한 칸을 움직이지만 자기 골키퍼 박스 안의 빈 칸으로 제한한다. 포지션은
이번 단계에서 초기 배치와 화면 라벨만 결정하며 이동 능력을 바꾸지 않는다.

## 6. 공통 공 경로

패스와 슛은 하나의 순수 경로 계산을 공유한다.

~~~text
출발 좌표 × 목표 좌표
→ 선분이 지나가거나 경계에 닿는 모든 보드 칸
→ 출발점 다음 칸부터 목표 방향으로 정렬된 좌표 목록
~~~

경로는 같은 입력에 항상 같은 결과를 반환한다. 선분이 정확히 칸 경계나 모서리에
닿으면 닿은 칸을 모두 포함해 화면상 경로에 걸친 기물이 판정에서 누락되지 않게 한다.
같은 진행 거리에서 모서리를 사이에 둔 두 칸의 기물을 동시에 만나면 더 낮은 `pieceId`의
기물이 먼저 공을 받는다. 이 동점 규칙은 팀과 공격 방향에 무관하며 탐색 결과를 결정론적으로 유지한다.
출발 기물의 칸은 결과에서 제외하고 패스 목표 칸은 포함한다. 슛 목표는 home 공격 시
(13, goalRow), away 공격 시 (-1, goalRow)의 보드 밖 골문 칸 중심이다. 슛 경로
결과에는 골문 전까지의 보드 내부 칸만 포함한다. 경로의 첫 기물은 팀과 포지션에
관계없이 공을 소유한다.

## 7. 패스

패스는 빈 칸이 아니라 아군 선수를 목표로 선택한다.

| 항목 | 규칙 |
|---|---|
| 목표 | 공 소유자 이외의 아군 |
| 거리 | max(abs(dx), abs(dy))가 6 이하 |
| 방향 | 제한 없음 |
| 막힌 패스 | 선택과 실행 모두 가능 |
| 빈 공간 패스 | 합법 수에서 제거 |

목표 아군까지의 경로를 검사해 처음 만난 기물이 실제 수신자가 된다.

- 목표 아군이 첫 기물이면 의도한 패스 성공
- 다른 아군이 먼저 있으면 그 아군이 공 소유
- 상대가 먼저 있으면 인터셉트

모든 경우 행동을 사용하고 턴이 끝난다.

## 8. 슛과 선방

공 소유자에서 공격 방향 골라인까지의 가로 거리가 7칸 이하이면 슛할 수 있다.
사용자는 기존 dy 기울기 대신 골문 행 3, 4, 5 중 하나를 직접 선택한다.

~~~text
슈터 좌표 × 선택한 골문 좌표
→ 공통 경로 계산
→ 경로의 첫 기물이 있으면 그 기물이 공 소유
→ 기물이 없으면 득점
~~~

필드 선수와 GK 모두 자신의 실제 칸이 경로에 포함될 때만 슛을 막는다. GK 전용
확률, 반응 선택, 인접 선방 범위는 없다. 막힐 슛도 합법 수이며 실행할 수 있다.

득점하면 점수를 올리고 모든 선수를 초기 진형으로 되돌린 뒤 실점 팀이 센터에서
킥오프한다.

## 9. 스틸

상대 공 소유자와 체비쇼프 거리 1인 아군은 스틸할 수 있다. 상하좌우뿐 아니라 대각선
인접도 포함한다.

~~~text
상대 공 소유자 직접 클릭
→ 가능한 아군 한 명이면 즉시 스틸
→ 가능한 아군 여러 명이면 사용할 아군 선택
→ 선택한 아군이 공 소유
~~~

스틸은 확률 없이 항상 성공한다. 성공 후 다음 상대 턴까지 재스틸할 수 없는 기존
한 턴 보호를 유지한다. 보호 중인 공 소유자에게는 방패를 표시하고 스틸 후보는
표시하지 않는다.

## 10. Move와 예상 결과 계약

사용자 의도가 타입에 직접 드러나도록 Move를 변경한다.

~~~ts
type Move =
  | { kind: "move"; pieceId: number; to: Pos }
  | { kind: "pass"; pieceId: number; targetPieceId: number }
  | { kind: "shoot"; pieceId: number; goalRow: 3 | 4 | 5 }
  | { kind: "steal"; pieceId: number; targetPieceId: number };
~~~

엔진은 상태를 변경하지 않는 예상 결과 API를 제공한다.

~~~ts
previewMove(state, move)
~~~

예상 결과의 공개 계약은 다음 정보를 표현한다.

- 이동: 최종 위치와 loose ball 획득 여부
- 패스: 순서가 보존된 경로, 실제 수신자 ID, 목표 도달 여부
- 슛: 순서가 보존된 경로, 득점 또는 차단 기물 ID
- 스틸: 새 공 소유자 ID와 한 턴 보호 발생

구체적인 TypeScript 유니온 이름은 구현 계획에서 정할 수 있지만 위 필드는 생략하지
않는다. applyMove()는 예상 결과와 같은 내부 판정을 사용해야 하며, 클라이언트는 선분
경로나 차단 규칙을 다시 구현하지 않는다.

## 11. 조작과 피드백

### 기본 흐름

~~~text
내 선수 선택
→ 이동·패스·슛 버튼 중 가능한 행동 표시
→ 행동 선택
→ Canvas 목표 선택
→ Move 적용
~~~

빈 공간 클릭은 선택을 해제한다. 봇 분석 중과 경기 종료 상태에서는 입력을 잠근다.

### 후보 표시

- 이동: 이동 가능한 빈 칸 표시
- 패스: 사거리 안의 모든 아군과 경로 표시
- 슛: 골문 위·중앙·아래와 각 경로 표시
- 스틸: 가능한 상대 공 소유자에게 직접 클릭 테두리 표시

의도한 결과가 나오는 패스·슛은 초록 실선과 체크 기호를 사용한다. 다른 기물이 먼저
공을 받는 패스나 막힐 슛은 빨간 실선과 경고 기호를 사용하고 실제 수신자·차단 기물을
강조한다. 색상만으로 의미를 구분하지 않는다. 초록·빨간 후보는 모두 클릭 가능하다.

스틸 가능한 아군이 여러 명이면 상대 공 소유자를 클릭한 뒤 가능한 아군만 강조한다.
아군을 클릭하면 스틸하고 빈 공간을 클릭하면 선택을 취소한다.

### 상황별 안내

보드 아래 한 줄은 현재 선택 상태에 따라 다음 조작을 설명한다.

~~~text
패스: 아군을 선택하세요. 빨간 경로는 중간 기물이 먼저 받습니다.
슛: 골문을 선택하세요. 빨간 경로는 표시된 선수에게 막힙니다.
스틸 가능: 테두리가 있는 상대 공 소유자를 클릭하세요.
스틸 보호: 방패가 사라진 다음 턴부터 스틸할 수 있습니다.
~~~

진행을 멈추는 팝업 튜토리얼은 추가하지 않는다.

## 12. 계층 책임과 데이터 흐름

~~~text
engine
  → 6대6 초기 상태
  → 합법 수
  → 공통 공 경로와 예상 결과
  → 실제 상태 전이
  → 평가와 탐색

client
  → 선수·행동·복수 스틸 선택 상태
  → 엔진 결과를 Canvas에 표시
  → 클릭을 Move로 변환
  → 상황별 안내

worker
  → 변경된 Move와 SearchResult 직렬화
  → 기존 requestId·5초 제한·최대 3회 재시도
~~~

엔진은 DOM과 Worker 전역을 참조하지 않고 결정론과 입력 불변성을 유지한다.

## 13. 오류와 성능 처리

- 불법 클릭은 상태를 바꾸지 않고 현재 선택에 맞는 안내를 유지한다.
- 경기 교체 또는 Worker 재시작 뒤 오래된 응답은 기존 gameEpoch로 무시한다.
- 봇 분석의 5초 제한과 최대 3회 자동 재시도는 유지한다.
- 6대6에서 깊이 3이 반복적으로 5초를 넘으면 완료로 처리하지 않는다.
- 사용자 승인 없이 봇 깊이를 낮추지 않는다.
- 성능 문제가 발생하면 후보 수, 수 정렬, 공통 경로 계산 재사용을 먼저 측정한다.

## 14. 자동 검증

엔진 테스트는 다음을 보호한다.

- 양 팀 6명과 좌표 중복 없는 미러 배치
- 필드 선수 공통 이동과 GK 박스 제한
- 임의 각도·경계·모서리에서의 공통 경로
- 최대 6칸 아군 지정 패스와 실제 첫 수신자
- 골문 세 행 직접 슛과 정확한 경로 차단
- 8방향 인접 스틸과 한 상대 턴 보호
- 예상 결과와 실제 상태 전이의 일치
- 입력 상태 불변성, 합법 수와 탐색의 결정론
- 3골과 전체 60 ply 종료
- 여러 자동 경기의 좌표·소유권·턴·점수 불변식

클라이언트 테스트는 다음을 보호한다.

- Canvas 대상과 새 패스·슛 Move의 왕복
- 초록 성공 경로와 빨간 차단 경로 표현
- 실제 수신자·차단 기물 강조
- 단일·복수 스틸 조작
- 보호 방패와 상황별 안내
- 봇 분석·종료 상태 입력 잠금

## 15. 실제 플레이테스트와 완료 기준

최소 세 경기를 실제 브라우저에서 플레이한다.

1. 설명 문서 없이 패스·슛·스틸을 조작할 수 있다.
2. 패스와 슛의 성공·차단 이유를 실행 전에 예측할 수 있다.
3. 한 경기 안에서 최소 한 번 이상 스틸 기회를 발견한다.
4. 원하는 아군과 골문을 직접 선택할 수 있다.
5. 깊이 3 봇 응수가 5초 제한 안에 끝난다.
6. 기존 버전보다 다시 플레이하고 싶은 느낌이 든다.

완료 전 다음 검증을 수행한다.

~~~powershell
npm run check
npm run build
git diff --check
git diff --exit-code -- reference/prototype.html
~~~

reference/prototype.html은 새 규칙의 런타임 의존성으로 만들거나 수정하지 않는다.
프로토타입과 의도적으로 달라진 규칙은 이 문서와 회귀 테스트를 근거로 삼는다.

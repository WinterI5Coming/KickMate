# KickMate FT&G 벤치마킹 경기 코어 개편 설계

- 작성일: 2026-08-22
- 상태: 제품 방향 승인, M2.6A 구현·자동 검증 완료, 스틸 회수 규칙 개정 승인·구현 전
- 범위: M2.6A 행동 경제·압박·슛 리바운드와 스틸 회수 규칙 개정
- 참고: *Football, Tactics & Glory*의 제한 행동 턴과 대결 구조를 원칙 수준에서 벤치마킹한다.

## 1. 결정 요약

KickMate의 우선 목표를 깊은 엔진 분석보다 **한 판이 짧고, 공수 선택의 결과가 즉시
드러나는 전술 축구**로 옮긴다. 현재 확인된 핵심 문제는 다음 두 가지다.

1. 낮은 득점: 슛 가능 국면이 적고 필드 선수가 슛을 막으면 공격이 즉시 끝난다.
2. 고착된 소유권: 수비수가 공 소유자에게 접근하고 같은 흐름에서 탈취할 행동 여유가
   부족해, 한번 공을 잡은 쪽이 안전하게 도망가기 쉽다.

전체 개편은 한 번에 확률과 성장 시스템까지 넣지 않고 세 단계로 나눈다.

| 단계 | 내용 | 목적 |
|---|---|---|
| M2.6A | 팀 턴당 3행동, 선수당 최대 2행동, 압박·버티기, 필드 슛 리바운드 | 현재 두 문제를 결정론 상태에서 먼저 해결 |
| M2.6B | 재현 가능한 확률 판정과 Pass·Shoot·Control·Defense 스탯 | 예측 가능성과 긴장감의 균형 검증 |
| M2.6C | 제한 포인트 배분과 프리셋 | 플레이 스타일과 재플레이성 추가 |

이 문서는 M2.6A만 구현 가능한 수준으로 확정한다. M2.6B와 M2.6C의 수치·UI·AI 계약은
M2.6A 플레이 결과를 확인한 뒤 별도 설계로 승인한다.

## 2. 제품 포지셔닝

목표 포지셔닝은 **5~8분 안에 끝나는 위험 관리형 캐주얼 전술 축구**다.

- 한 턴에 전진, 압박, 패스 또는 슛을 조합해 작은 공격 장면을 만든다.
- 결과는 읽기 쉬워야 하고, 실패해도 다음 공방을 만드는 방향으로 이어져야 한다.
- 엔진 평점과 블런더 리뷰는 차별화 후보로 남기되 핵심 재미가 검증될 때까지 후순위다.
- 커리어, 선수 육성, 다수 클래스, 반복 파밍은 현재 범위에 포함하지 않는다.

FT&G에서 가져오는 것은 제한된 행동 수, 선수 능력 간 대결, 압박과 공 지키기라는
설계 원칙이다. KickMate의 13×9 보드, 6대6, 정확한 공 경로, 실행 전 미리보기,
루즈볼 전환은 유지한다.

## 3. M2.6A 규칙

### 3.1 팀 턴과 행동 포인트

- 한 팀 턴을 시작할 때 행동 포인트를 3 받는다.
- `move`, `pass`, `shoot`, `steal`, `hold`는 각각 행동 포인트 1을 소비한다.
- 같은 선수는 한 팀 턴에 최대 2번 행동할 수 있다.
- 행동 포인트가 0이 되면 상대 팀 턴으로 넘어간다.
- 한 번 이상 행동한 뒤에는 남은 포인트를 버리고 턴을 끝낼 수 있다. `endTurn` 자체는
  경기 행동 수를 늘리지 않으며, 0행동 종료는 무한 반복을 막기 위해 허용하지 않는다.
- 기존 `turn`은 지금까지 실행된 원자 행동 수를 뜻하며 최대 60을 유지한다. 따라서
  60행동 또는 3골 선취에서 경기가 끝난다.
- 득점 행동은 행동 수를 1 늘린 뒤 즉시 실점 팀에게 새 3행동 턴을 준다.

필요한 상태 개념은 다음과 같다. 실제 필드명은 구현 계획에서 기존 호출자와 직렬화
영향을 확인한 뒤 확정한다.

```ts
interface TeamTurnState {
  activeTeam: Team;
  actionsRemaining: 0 | 1 | 2 | 3;
  actionCountByPiece: Record<number, 0 | 1 | 2>;
  heldFirmPieceId: number | null;
}
```

`sideToMove()`는 더 이상 `turn`의 홀짝이 아니라 `activeTeam`을 기준으로 한다. 탐색도
한 행동 뒤 같은 팀이 계속 행동할 수 있으며, 팀이 바뀔 때만 관점이 바뀐다.

### 3.2 압박과 버티기

별도의 `press` 버튼은 만들지 않는다. 상대 선수가 공 소유자와 8방향으로 인접하면
그 배치 자체가 압박이다.

- 압박받지 않는 공 소유자는 기존과 같이 이동할 수 있다.
- 압박받는 공 소유자는 바로 이동할 수 없고 패스, 슛, 버티기 중 하나를 선택한다.
- `hold`는 압박받는 공 소유자만 사용할 수 있다. 행동 1을 소비하고 그 선수에게 이번
  팀 턴의 다음 이동 1회만 허용한다.
- 버틴 뒤 이동하면 허가가 사라진다. 패스, 슛, 소유권 변경, 득점, 팀 턴 종료 때도
  남은 허가를 제거한다.
- 버티기는 팀 행동 1만 소비하고 선수별 행동 횟수에는 포함하지 않는다. 따라서 버틴 뒤
  이동에 선수 행동 1을 쓰고도 같은 팀 턴에 패스하거나 슛할 선택을 한 번 남긴다.
- `stealProtection` 보호 중에도 압박과 버티기는 적용한다.
- 상대 기물 한 명만 보호 소유자에게 인접하면 보호를 유지한다.
- 상대 기물 두 명 이상이 보호 소유자에게 인접한 `포위` 상태면 보호를 무시하고 인접
  기물이 즉시 스틸할 수 있다. 대각선 인접도 인원에 포함한다.

`stealProtection`은 팀 턴 전체 면역이 아니라 **공을 잃은 팀의 다음 원자 행동 하나**를
막는 회수 유예다. 보호받는 새 소유자, 스틸이 잠시 금지된 팀, 그 팀이 앞으로 완료해야
할 보호 행동 수 `1`을 기록한다. 차단 팀이 `move`, `pass`, `shoot`, `steal`, `hold` 중
합법 행동 하나를 완료하면 보호를 해제한다. `endTurn`으로 남은 행동을 버려도 보호를
해제해 다음 팀 턴으로 넘길 수 없게 한다. 포위로 보호를 무시해 스틸하더라도 기존 보호
상태를 먼저 소비할 필요는 없다.

새 보호는 다음과 같이 소유권을 얻은 모든 경로에 같은 기준으로 적용한다.

- 상대에게서 직접 성공한 스틸
- 상대 패스를 가로챈 기물의 소유
- GK 선방과 빈 리바운드 칸이 없어 필드 차단자가 얻은 소유
- 루즈볼 칸에 이동해 새로 얻은 소유

같은 팀 안에서 성공한 일반 패스와 득점 뒤 킥오프에는 새 보호를 만들지 않는다. 공이
다시 패스·슛·스틸로 소유자를 떠나거나 루즈볼이 되면 기존 보호는 즉시 해제한다.

이 규칙은 공을 잃은 팀이 `재배치 1회 → 스틸`로 한 팀 턴 안에 재도전하게 하면서도,
소유권 변경 직후 한 명의 인접 선수만으로 즉시 왕복 스틸하는 현상을 막는다. 이미 두
명이 협력해 포위한 수비는 첫 행동부터 스틸할 수 있으므로 사전에 만든 압박 배치가
실제 탈취 보상으로 이어진다.

### 3.3 슛 차단과 리바운드

- 정확한 슛 경로와 첫 충돌 기물 계산은 유지한다.
- 슛 경로의 아군 필드 선수는 차단자로 취급하지 않고 공이 통과한다.
- 첫 상대 차단자가 GK면 GK가 공을 잡고 현재 슈팅 팀의 다음 행동 1회 동안 `stealProtection`을 받는다.
- 첫 상대 차단자가 필드 선수면 공을 잡지 않고 그 선수 주변의 빈 칸으로 루즈볼이
  튄다. 빈 인접 칸이 하나도 없을 때만 차단자가 직접 소유하고 다음 행동 1회 보호를 받는다.
- 리바운드 후보는 차단자의 8방향 인접 칸 중 보드 안이며 비어 있는 칸이다.
- 후보는 슈터와의 거리 제곱이 작은 순서, `y`가 작은 순서, `x`가 작은 순서로 정렬해
  첫 칸을 선택한다. 즉 리바운드는 대체로 슈터 쪽으로 돌아오며 항상 재현 가능하다.
- 빈 후보가 하나도 없으면 차단한 필드 선수가 공을 소유하되 스틸 보호는 받지 않는다.

막힌 슛이 곧바로 안전한 상대 소유권으로 끝나지 않게 해 박스 근처의 두 번째 공방을
늘리는 것이 목적이다.

## 4. 엔진·탐색·UI 영향

### 엔진

- `GameState`에 팀 턴 상태를 추가하고 득점·종료·킥오프 경계에서 초기화한다.
- `Move`에 `hold`, `endTurn`을 추가한다.
- 합법 수 생성은 남은 행동, 선수별 행동 횟수, 압박, 버티기 허가를 함께 검사한다.
- 상태 전이는 계속 입력 상태를 변경하지 않으며 `Math.random()`을 사용하지 않는다.

### 탐색

- 깊이는 원자 행동 수로 계산한다.
- 평가는 항상 루트 팀 관점으로 고정한다. 자식의 `activeTeam`이 루트 팀이면 최댓값을,
  상대 팀이면 최솟값을 선택한다. 이전 버전의 매 행동 네가맥스 부호 반전은 사용하지 않는다.
- 같은 팀의 연속 행동으로 분기 수가 증가하므로 기존 depth 3을 몰래 낮추지 않는다.
  대표 국면의 후보 수·노드 수·5초 제한을 먼저 측정하고 수 정렬과 중복 계산을
  프로파일링한다.

### 클라이언트

- 현재 팀, 남은 행동 `3/3`, 선택 선수의 이번 턴 행동 `0/2`를 표시한다.
- `버티기`와 `턴 종료` 버튼을 추가한다.
- 압박받는 공 소유자와 버티기 후 이동 가능 상태를 보드에서 구분한다.
- 필드 슛 차단 미리보기는 `차단 후 루즈볼 예상 칸`까지 보여준다.
- 봇은 한 행동이 아니라 `activeTeam`이 home으로 바뀌거나 경기가 끝날 때까지 연속으로
  분석·적용한다.

## 5. 테스트 우선 구현 범위

구현 과정에서 다음 실패 테스트를 먼저 추가해 회귀 계약으로 남겼다.

1. 팀 턴 시작 3행동, 행동별 감소, 0에서 팀 교대
2. 같은 선수 2행동 제한과 다른 선수의 남은 행동 사용
3. 1행동 이후 조기 종료와 0행동 종료 금지
4. 득점 후 실점 팀 3행동 킥오프, 60번째 원자 행동 종료
5. 모든 소유권 획득 경로의 1행동 `stealProtection`, 행동·턴 종료에 따른 만료
6. 보호 중 1인 압박의 스틸 금지와 2인 포위의 즉시 보호 무시
7. 압박 중 이동 금지, `버티기 → 이동`, 허가 제거
8. 슛 경로 아군 통과, GK 선방, 필드 차단 루즈볼, 후보가 없는 예외
9. 같은 팀 연속 행동과 팀 교대에서 탐색 관점이 올바른지 검증
10. Controller가 봇의 팀 턴 전체를 처리하고 사람 입력을 중간에 열지 않는지 검증
11. 입력 상태 불변성, 보드 경계, 좌표 중복, 종료 상태 합법 수 없음 회귀

`npm run check`, `npm run build`, `git diff --check`와 초기·압박 depth-3 5초 기준은 통과했다.
반복 브라우저 응답 시간은 실제 세 경기에서 후속 검증한다.

## 6. 플레이테스트 판정

자동 검증 뒤 같은 빌드로 최소 세 경기를 플레이한다. 각 경기에서 다음을 기록한다.

- 총 슛 수와 득점 수
- 필드 차단 리바운드 수와 리바운드 후 슛·소유권 변경 여부
- `이동 → 스틸` 시도·성공 수
- `버티기 → 이동` 사용 수
- 한 팀이 6행동 이상 연속으로 공을 유지한 구간 수
- 경기 시간과 즉시 재경기 의향

M2.6A의 목표는 특정 득점률을 미리 맞추는 것이 아니라, 이전 버전보다 슛과 탈취
시도가 눈에 띄게 늘고 막힌 슛 뒤에도 플레이가 이어지는지 확인하는 것이다. 개선이
없다면 확률을 먼저 추가하지 않고 행동 수, 선수 행동 제한, 압박 규칙을 다시 조정한다.

## 7. M2.6B·C로 넘기는 결정

다음 항목은 이번 구현에 포함하지 않는다.

- D6 또는 다른 확률 분포
- 시드와 확률 결과 열거를 포함한 탐색 계약
- Pass, Shoot, Control, Defense의 실제 수치와 역할별 차이
- 스탯 포인트 총량, 최소·최대치, 프리셋
- 확률 미리보기의 정확한 퍼센트 또는 위험 구간 표현
- 선수 성장, 커리어, 특수 스킬, 무료 행동 연쇄

M2.6B 설계 때는 실제 적용 결과와 AI 탐색이 재현되도록 상태 기반 시드를 사용하고,
UI 미리보기와 탐색이 같은 결과 모델을 공유해야 한다. 엔진에서 `Math.random()`을 직접
호출하지 않는다는 불변 조건은 유지한다.

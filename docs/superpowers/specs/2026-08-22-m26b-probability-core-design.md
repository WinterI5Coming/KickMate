# M2.6B 확률 판정 코어 설계

- 작성일: 2026-08-22
- 상태: 구현·자동 테스트 검증 완료, 사용자 플레이 검증 전
- 상위 문서: [게임 정책](../../game-policy.md), [FT&G 벤치마킹 경기 코어 개편 설계](./2026-08-22-ftg-inspired-match-core-design.md)

## 1. 문제 정의

2026-08-22 사용자 플레이에서 다음 세 문제가 보고됐다.

1. 슛 각이 거의 나오지 않고, 막힌 슛은 시도할 가치가 전혀 없다.
2. 봇에게 공을 잃으면 다시 뺏은 경험이 0회다.
3. 슛이 날아올 위치에 선수를 배치해도 골이 들어간다.

자동 입력 10경기에서도 차단 슛 득점 0%, 열린 슛 100%의 전략 단절이 확인됐다. 세
문제의 공통 원인은 패스·슛 판정이 정확한 선분 기하의 100/0 결정론이라는 점이다.
FT&G가 재미를 만드는 확률 대결과 수비 영향권이 없어서, 수비는 정확한 칸 하나를
점유해야만 의미가 있고 공격은 완전히 열린 선분을 찾는 퍼즐로 축소된다.

## 2. 목표와 비목표

목표:

- 막힌 슛에도 기대값을 부여해 "지금 지를까"라는 위험 관리 선택을 만든다.
- 공 경로 근처의 수비 배치가 확률적으로 보상받게 한다(패스 인터셉트, 슛 차단).
- 재현 가능성 정책(2.2)을 유지한다. 같은 국면의 같은 수는 언제나 같은 결과다.
- 봇이 판정 결과를 미리 아는 부정을 막는다.

비목표(후속 단계):

- Pass·Shoot·Control·Defense 4스탯과 포인트 배분. 확률 코어 검증 뒤 도입한다.
- 슛 거리별 확률 감쇠, 스틸 확률화. 스틸은 사람의 유일한 회수 수단이므로 100%를
  유지한다.

## 3. 확률 관문 모델

패스와 슛은 공 경로(`traceBallPath`)를 진행 순서대로 걸으며 **관문(BallGate)**을
수집한다. 한 기물은 한 번의 공 이동에서 최대 한 번만 개입을 시도한다.

| 관문 | 조건 | 개입 확률 | 상태 |
|---|---|---:|---|
| 슛 경로 위 상대 필드 선수 | 경로 칸 점유 | 65% | [실험 중] |
| 슛 경로 위 상대 GK | 경로 칸 점유 | 75% | [실험 중] |
| 경로 인접 상대(영향권) | 경로 칸에 체비쇼프 거리 1, 경로 위가 아님 | 20% | [실험 중] |

- 같은 시점(PathStep)에서는 영향권 개입을 점유 접촉보다 먼저, 후보 여럿은 ID
  오름차순으로 평가한다.
- 패스는 팀과 관계없이 경로를 점유한 첫 기물이 100% 수신자이며 거기서 경로가 끝난다.
  영향권 개입은 수신 칸까지의 경로에 적용된다.
- 슛은 아군을 통과하고 상대 점유자만 관문이 된다. 모든 관문을 통과하면 득점이다.
- 개입 성공의 상태 전이는 기존 결정론 규칙을 재사용한다. GK 개입 = 선방 소유 + 회수
  유예, 필드 개입 = 리바운드 루즈볼 또는 차단자 소유 + 유예, 패스 영향권 개입 =
  인터셉터 소유 + 유예.

대표 체감 수치: 완전 열린 슛 100%, 필드 수비 1명 뒤 슛 35%, 필드+GK 뒤 슛 약 9%,
영향권 수비 2명을 지나는 패스 64%.

## 4. 결정론적 판정 시드

- `applyMoveOutcomes(state, move)`는 가능한 결과와 확률(합 1)을 열거한다.
- `applyMove(state, move)`는 상태의 게임 결정 요소(턴, 팀, 행동 수, 점수, 공, 기물
  좌표)와 Move를 FNV-1a 32비트로 해시한 롤(0..1)로 결과 하나를 고른다.
- `Math.random()`과 실행 시각은 계속 금지한다. 기보만 있으면 모든 판정을 재실행할
  수 있고, 결정론·불변성 테스트도 그대로 성립한다.

## 5. 탐색 계약

- 탐색은 `applyMove()` 대신 `applyMoveOutcomes()` 분포의 확률 가중 합으로 수를
  평가한다(expectiminimax). 해시 롤의 실제 결과를 탐색에서 사용하는 것은 정책
  위반이다.
- 결과가 하나뿐인 수는 기존 알파베타 창을 물려받고, 확률 분기는 각각 전체 창으로
  평가한다. 수 정렬의 rank 100은 "득점 확률 1"인 슛으로 재정의한다.
- `evalLv1`의 EV-04는 가장 유망한 슛의 득점 확률에 450을 비례 적용한다.
- 성능: 대표 두 국면의 depth-3 탐색이 병렬 테스트 부하에서 3~4초로 5초 기준을
  통과했다(종전 약 0.6초). 반복 브라우저 체감 측정이 필요하며, 초과 시 확률 분기
  가지치기(Star1)나 깊이 조정을 검토한다.

## 6. 클라이언트 표시

- 패스 미리보기: 첫 수신자 도착 확률 `arrivalChance`를 %로 표시. 기하적으로 다른
  기물이 먼저 받는 패스는 기존대로 `!`를 유지한다.
- 슛 미리보기: 득점 확률 `goalChance`를 %로 표시. 성공 색은 확률 1일 때만 사용한다.
- 슛 위협 레인: 사람 턴에 away 공 소유자가 슛 거리 안이면 골문 세 행의 위협 경로를
  득점 확률에 비례한 진하기로 깔고, 왼쪽 골문 옆에 확률 %를 표기한다. 수비 배치
  판단의 추측을 제거하는 것이 목적이다.
